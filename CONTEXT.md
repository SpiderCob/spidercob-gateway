## What this is

Open-source MCP gateway: spec-correct agent identity (ID-JAG / MCP Enterprise-Managed Authorization) plus policy and DLP, in one container. Launches together with **spider-snoop** (the parent Spidercob product) as one integrated product, not two separate logins. Full north star: `MASTER_PLAN.md` §0 on `main`.

- **Issue #21, what landed — and the real architectural fork it resolved:**
  - CSV import is for local Mode A humans, but `internal/adminapi` (and every admin UI screen on top of it, issues #17/#19) is entirely gated on spider-snoop integration (`Config.AdminAPIEnabled()`). A standalone (no-spider-snoop) deployment — the one the README's "no IAM department" pitch actually describes — has **no admin surface at all today**, so an admin-API/UI-shaped CSV import would be unreachable for exactly the deployment that needs it. Rather than build that unreachable feature, or take on a whole standalone-admin-login project as unplanned scope, this shipped as a **config-bootstrap mechanism**, mirroring exactly how `SeedAgents`/`Policies`/`mcp_nodes` already bootstrap from `config.json`.
  - `internal/config`: new `SeedUser{Username, Password, Groups}` + a pure `ParseSeedUsersCSV(io.Reader) ([]SeedUser, error)` (no file I/O in the parsing logic, same posture `ValidateNode` established for issue #15). Header-based column lookup (`username`/`password`/`groups`, case-insensitive, any order), `groups` split on `;` (not `,`, already the CSV's delimiter). Fails loud — never skip-and-continue — on a missing required header column, an empty username/password value, or a duplicate username within the file.
  - `internal/config`: new `Config.SeedUsersCSVPath`. `Load` reads and parses the referenced file; missing/unreadable/malformed content is a `Load` error, same fail-loud posture a malformed `config.json` itself already has. Absent path is a complete no-op.
  - `cmd/spidercob`: new bootstrap loop alongside the existing `SeedAgents` loop, reusing the exact same machinery (`identitySvc.CreateUser`, `getOrCreateGroup`, `store.AssignUserGroup`). **Idempotency mirrors `SeedAgents`, not `Policies`/`mcp_nodes`:** create-if-missing, group assignment always reconciled (so adding a group to an existing row and restarting still takes effect), but an existing user's password is **never** reset by a later run — even if the CSV file itself changes.
  - `automation/run-e2e-seed-users.sh` (new, wired into `make ci`): a real CSV-seeded user's real password authenticates against `/token`'s login grant and drives a real, policy-authorized `tools/call` — then, mirroring `run-e2e-nodes.sh`'s real-restart technique, the compiled binary is killed and relaunched against an *edited* CSV (same username, changed password) and the **original** password is confirmed to still be the one that works, proving the never-reset guarantee for real, not just as a doc comment.
  - **The standalone-admin-login gap this issue deliberately sidesteps is now explicitly named** in `MASTER_PLAN.md` §7's open-decisions list (not left implicit): a no-spider-snoop deployment still has no way to reach any `/admin/*` surface at all. Needs a real design pass before any further admin-API/UI feature can meaningfully target that deployment shape.
- `make ci` now runs **eleven** Docker-free layers (added `run-e2e-seed-users.sh`). `make ci-interop` (real Keycloak, Docker-required) is unaffected and still green.
- **`MASTER_PLAN.md` §3 step 10c-3** is now `[x]`, with the divergence from its original "`/admin/users/import`"-shaped framing explicitly noted, not silently reinterpreted.

## Next up

The audit viewer specifically is blocked on `internal/audit` not existing yet (today's admin actions are `slog`-logged, not a queryable/hash-chained trail) — that's a real, separate backend-infrastructure issue in its own right, bigger than a UI screen, distinct from the viewer itself.
