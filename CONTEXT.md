## What this is

Open-source MCP gateway: spec-correct agent identity (ID-JAG / MCP Enterprise-Managed Authorization) plus policy and DLP, in one container. Launches together with **spider-snoop** (the parent Spidercob product) as one integrated product, not two separate logins. Full north star: `MASTER_PLAN.md` §0 on `main`.

Don't assume it's running — `gh pr view <n> --json reviews` will show whether a review actually posted; if none does, that's expected now, not a sign to wait longer. If it's ever re-enabled, the lesson below still applies.
- **Issue #49 (goreleaser signed releases + `brew install`) — spec'd and built in the same session, right after issue #45.** Closes out `docs/design.md` §11/§13.2's last pre-launch-checklist release-engineering item. Worth knowing if this area comes up again:
  - **Signing: Sigstore/cosign keyless**, confirmed with the user over GPG-signed checksums — GitHub Actions' own OIDC identity signs `checksums.txt`, no private key to custody.
  - **Real, confirmed incompatibility caught during the build, not a hypothetical**: cosign v3 hard-requires `sign-blob --bundle` (the older `--output-signature`/`--output-certificate` pair is rejected outright). Verified directly against real installed cosign binaries. Then, separately, **pinning `sigstore/cosign-installer` to an exact cosign version (v3.1.3) broke real CI** — a 404 fetching a `.sig` file cosign's own release process no longer publishes for recent tags, a genuine mismatch between the installer action's custom-version verification code path and cosign's current release asset layout. Fixed by *not* pinning at all and relying on the installer action's own tested default (v3.0.6 at the time) — confirmed to support `--bundle` too.
  - **`-version` flag added to the binary** (`cmd/spidercob/main.go`) — didn't exist before this issue. `main.version`/`commit`/`date` vars, `-X`-ldflag-injected by goreleaser, default `dev`/`none`/`unknown` for a plain `go build`.
  - **The real seam-check finding**: no application-level unit-test seam exists for "does a cross-compiled, signed release actually work" — release tooling, not application logic. Answer: goreleaser's own `--snapshot` dry-run mode (no tag, no publish, no network), scripted into `automation/run-e2e-release.sh`, asserting on real output (a real archive actually extracted and executed, `-version` output checked, checksums verified against real bytes). The signing half specifically needed a real CI-issued OIDC token (unfakeable locally) — proven instead by a PR-triggered snapshot job in the release workflow, confirmed actually passing for real in CI.
  - **A real, named prerequisite still outside any diff**: creating the `SpiderCob/homebrew-tap` repo and its `HOMEBREW_TAP_GITHUB_TOKEN` secret is a manual, org-level, one-time action nobody has done yet — the release job gracefully skips just the Homebrew-publish target until then (confirmed this doesn't fail the rest of the release).
  - **No tag has actually been pushed yet** — the whole pipeline is built and proven (snapshot dry run locally + real signing round-trip in CI), but there is still no live GitHub Release or working `brew install` today. README's "Installing a release" section says this explicitly.
  - Landed as **[PR #50](https://github.com/SpiderCob/spidercob-gateway/pull/50)**, merged — after a real review-fix round (4 confirmed findings: a `set -e`-swallowed checksum-verification exit code in the e2e script, an unbound-variable risk in its EXIT trap when `goreleaser` is missing, a mutating `go mod tidy` release-build hook replaced with non-mutating `go mod tidy -diff`, and the release job's Homebrew-publish step made to skip gracefully instead of failing the whole release when the tap token is absent).
- **Issue #45 (per-MCP-request audit trail)** — spec'd and built the same session, right before #49; extends the hash-chained audit trail to actual MCP traffic (not just admin actions), async bounded write queue, three follow-up PRs (#47/#48) fixing real Copilot-review findings post-merge. Full detail in `MASTER_PLAN.md` if it matters for what you're doing, not repeated here.
- **Issue #43 (standalone admin login)** and earlier issues (#35, #37, #39, #41) — all done in prior sessions of this same arc; full detail in `MASTER_PLAN.md`.
- **Standing lesson from this whole session's PRs, independent of whether Copilot review is on**: verify claims about third-party tools (goreleaser, cosign, a GitHub Action's defaults) against the real thing before shipping a config that depends on them — three separate real incompatibilities (cosign's `--bundle` requirement, the installer action's version-pin behavior, `go mod tidy`'s mutation risk) were each caught by actually running the real tool locally or in real CI, not by reading docs alone.
