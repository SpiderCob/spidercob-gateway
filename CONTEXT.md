# Spidercob Gateway — Current State

**Read this first in a new session with no memory of prior conversations.** For the full plan and rationale, see `MASTER_PLAN.md` and `docs/design.md` on `main` — this file is a rolling snapshot, not a replacement for those. It lives on this orphan branch (`context_main`) deliberately, separate from `main`'s code history — nothing to check out here, just a doc to read. See `CLAUDE.md` on `main` for the update procedure and why this is a different thing from any future domain-glossary `CONTEXT.md`.

## What this is

Open-source MCP gateway: spec-correct agent identity (ID-JAG / MCP Enterprise-Managed Authorization) plus policy and DLP, in one container. Launches together with **spider-snoop** (the parent Spidercob product) as one integrated product, not two separate logins. Full north star: `MASTER_PLAN.md` §0 on `main`.

- **Issue #25, what landed:**
  - `internal/store`: new `ListAuditRecordsPage(ctx, limit, beforeID)`, deliberately distinct from the existing `ListAuditRecords` — the latter stays completely untouched (still full-chain, ascending order, `verifychain`'s real need from issue #23). Descending id (most recent first); `beforeID=0` starts from the most recent record, a non-zero `beforeID` returns strictly older ones. New `DefaultAuditPageSize`/`MaxAuditPageSize` constants — a non-positive `limit` falls back to the default, an over-large one is clamped, so a single request can never force the whole table to serialize.
  - `internal/adminapi`: new `GET /admin/audit`, `gateBrowserOrService`-gated from the moment it shipped — **unlike `/admin/nodes`'s issue #17→#19 staged widening, no initial service-to-service-only restriction**, since a read-only viewing endpoint has no dual-trust reason to start narrower and the UI screen needs the cookie path immediately. `limit`/`before_id` query params; malformed values fall back to defaults rather than 400ing. Response includes `hash`/`prev_hash` per record even though this issue builds no verification UI on top of them (so a later "chain-intact indicator" feature doesn't need a second endpoint change). **Deliberately does not expose `audit.Verify` over HTTP** — an O(n) full-chain recompute has no business in a listing request's hot path; that stays `verifychain`'s job.
  - `web/`: new **Audit** screen, the admin UI's fifth tab — read-only table (no create/delete form, this resource has no admin-authored mutations), a "load older" control that fetches the next page via the last-seen record's `id` as `before_id` and **appends rather than replaces**, so the admin's scroll position and already-loaded context don't reset on every fetch.
  - `automation/run-e2e-audit.sh` — **extended, not a new script** (still one "audit trail" lifecycle, per this repo's own stated convention): new checks before the existing file-direct tamper-evidence proof confirm all three real admin operations are retrievable via the real HTTP endpoint (both credential shapes — an NHI token, and a cookie alone with no NHI token anywhere in that request), most-recent-first ordering, and real `before_id` pagination proven to return a strictly older, non-overlapping page. The pre-existing `verifychain`/`corruptrow` tamper-evidence proof at the end is unchanged.
  - **`MASTER_PLAN.md` §3's 10c-5** (previously a placeholder explicitly blocked on this exact endpoint not existing) is now `[x]`.
- `make ci` still runs **twelve** Docker-free layers (issue #25 extended `run-e2e-audit.sh` rather than adding a new one — now 18 checks in that one script). `make ci-interop` (real Keycloak, Docker-required) is unaffected and still green.
- **The admin UI now covers five of its eventual screens**: agents, groups, policies, nodes, audit.

## Next up

**Phase 4c-6+ — kill-session button, config-snippet generator, or `deploy/` packaging** (all independent). Kill-session needs a new admin endpoint first — no session-termination API exists yet for MCP sessions specifically, distinct from the `uisession` (browser login) concept. Config-snippet generator is pure UI polish, no backend change. Also still open and unspec'd: the **standalone-admin-login gap** (`MASTER_PLAN.md` §7 — a no-spider-snoop deployment still can't reach any `/admin/*` surface at all) and the bigger, separately-scoped **per-MCP-request audit trail** (`docs/design.md` §6's original fuller vision, wiring `internal/audit` into `internal/proxy`'s hot path — real latency-budget considerations, deserves its own seam-check). Run `/to-spec` for whichever slice comes next.

**Secondary, not urgent:** `make ci-interop` still doesn't run in GitHub Actions CI (needs Docker + network egress, unconfirmed on the self-hosted Hetzner runner) — `MASTER_PLAN.md` §7, unresolved across several issues now. The GitHub Actions workflow still runs plain `gofmt`/`go vet`/`go build`/`go test` (no `make web`/npm step) — fine today since `internal/webui/dist`'s tracked `.gitkeep` keeps the Go build green without Node.js, but CI isn't currently proving the frontend actually builds. **Local-dev gotcha, now hit five times (issues #17, #19, #21, #23, #25):** a real `npm run build` (Vite's `emptyOutDir: true`) wipes the tracked `internal/webui/dist/.gitkeep` placeholder — `git status` shows it deleted after building the frontend locally, or after running `make ci`/`make web` at all (they both depend on `make web`); `touch` it back before committing.
