# Spidercob Gateway — Current State

**Read this first in a new session with no memory of prior conversations.** For the full plan and rationale, see `MASTER_PLAN.md` and `docs/design.md` on `main` — this file is a rolling snapshot, not a replacement for those. It lives on this orphan branch (`context_main`) deliberately, separate from `main`'s code history — nothing to check out here, just a doc to read. See `CLAUDE.md` on `main` for the update procedure and why this is a different thing from any future domain-glossary `CONTEXT.md`.

## What this is

Open-source MCP gateway: spec-correct agent identity (ID-JAG / MCP Enterprise-Managed Authorization) plus policy and DLP, in one container. Launches together with **spider-snoop** (the parent Spidercob product) as one integrated product, not two separate logins. Full north star: `MASTER_PLAN.md` §0 on `main`.

- **Issue #19, what landed:**
  - **Backend: `gateBrowserOrService` (issue #17) extended to `/admin/nodes`.** Nodes were issue #17's one deliberate holdout — kept service-to-service-only until a real node-registration screen existed to justify widening the cookie path. The change was a one-line-per-route swap (`a.gate` → `a.gateBrowserOrService`) on the three existing routes; no changes to `config.ValidateNode`/`createNode`/`deleteNode`/`listNodes` themselves. A cookie-authenticated delete of a `config`-sourced node is refused with the exact same 409 message the NHI path already produced. The pre-existing NHI-token-plus-header path proven completely unaffected (existing test suite passes unmodified).
  - **`web/`: new `Nodes` screen**, mirroring the Agents/Groups list/create/delete pattern. Transport-conditional create form (streamable_http needs an upstream URL, stdio needs a command+args). A persistent, visually-distinct-from-the-Agents-screen's-secret-banner notice appears on every newly-registered node: it won't route traffic or accept a minted token until the gateway restarts — issue #15's real, unchanged restart-required behavior; this issue only makes the UI honest about it, it does **not** add hot-reload. Deleting a `config`-sourced node surfaces the backend's 409 message verbatim, same principle the Groups screen already applies to its own 409.
  - **`automation/run-e2e-adminui-nodes.sh`** (new, wired into `make ci`): narrowly proves the cookie now works on `/admin/nodes` against the real compiled binary — login via cookie (no NHI token anywhere in the script), list a config-sourced node, register a new node, confirm it's persisted, confirm deleting the config-sourced node is refused with the right message, confirm deleting the newly-registered node succeeds. Deliberately does **not** re-prove restart-required behavior — that stays `run-e2e-nodes.sh`'s job, unmodified.
  - **`automation/run-e2e-adminui-session.sh`** (issue #17's script) updated: dropped its now-stale assertion that the cookie is rejected on `/admin/nodes` — that specific behavior legitimately changed in this issue, and is now covered by the new script instead.
- `make ci` now runs **ten** Docker-free layers (added `run-e2e-adminui-nodes.sh`). `make ci-interop` (real Keycloak, Docker-required) is unaffected and still green.
- **`MASTER_PLAN.md` §3 step 10c-2** is now `[x]`, with a DoD description mirroring 10c-1's. 10c-1's own writeup was lightly amended (not rewritten) to note it was later widened, since its original text said the cookie was "never accepted on `/admin/nodes`" — that's no longer true and the doc now says so explicitly rather than leaving a stale claim standing.
- **The admin UI now covers four of its eventual screens**: agents, groups, policies, nodes. Remaining, per `MASTER_PLAN.md` §3's 10c-3 through 10c-5: CSV bulk user import (backend-heavy, doesn't depend on the UI), audit viewer (blocked on `internal/audit` not existing yet), kill-session button / config-snippet generator / a real policy-matrix visualization (v0's Policies screen ships a plain list/replace form, not the matrix).

The GitHub Actions workflow (`.github/workflows/ci.yml`) still runs plain `gofmt`/`go vet`/`go build`/`go test` (no `make web`/npm step) — fine today since `internal/webui/dist`'s tracked `.gitkeep` keeps the Go build green without Node.js, but CI isn't currently proving the UI's frontend actually builds, only that the Go side tolerates it being absent. **Local-dev gotcha worth knowing:** a real `npm run build` (Vite's `emptyOutDir: true`) wipes the tracked `internal/webui/dist/.gitkeep` placeholder from disk — `git status` will show it as deleted after building the frontend locally; `touch` it back before committing if your change touches anything in `web/` (both issue #17 and #19's PRs hit this, same fix each time).
