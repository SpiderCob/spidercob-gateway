# Spidercob Gateway — Current State

**Read this first in a new session with no memory of prior conversations.** For the full plan and rationale, see `MASTER_PLAN.md` and `docs/design.md` on `main` — this file is a rolling snapshot, not a replacement for those. It lives on this orphan branch (`context_main`) deliberately, separate from `main`'s code history — nothing to check out here, just a doc to read. See `CLAUDE.md` on `main` for the update procedure and why this is a different thing from any future domain-glossary `CONTEXT.md`.

## What this is

Open-source MCP gateway: spec-correct agent identity (ID-JAG / MCP Enterprise-Managed Authorization) plus policy and DLP, in one container. Launches together with **spider-snoop** (the parent Spidercob product) as one integrated product, not two separate logins. Full north star: `MASTER_PLAN.md` §0 on `main`.

## Where things stand (as of 2026-08-08)

- **Phase 3 is fully complete, and Phase 4's first two slices are done and merged.** [PR #14](https://github.com/SpiderCob/spidercob-gateway/pull/14) (issue #13) shipped the admin API backend. [PR #16](https://github.com/SpiderCob/spidercob-gateway/pull/16) just merged, closing [issue #15](https://github.com/SpiderCob/spidercob-gateway/issues/15) — MCP nodes are now persisted in the store and registrable over HTTP via `/admin/nodes`, not just `config.json`.
- **Issue #15, what landed:**
  - `internal/config.ValidateNode(Node) (Node, error)` — extracted as a pure function from `config.Load`'s existing per-node validation (name required/no slash/no leading-or-trailing whitespace, transport defaults to `streamable_http`, `streamable_http` requires `upstream_url`, `stdio` requires `command`, unknown transport errors). Reused as-is by the new admin node-create endpoint, so `config.json` and `POST /admin/nodes` enforce identical rules.
  - `internal/store`: new `mcp_nodes` table (migration `0007`) + Node CRUD (`CreateNode`, `GetNodeByName`, `ListNodes`, `DeleteNode`), plus `UpsertConfigNode`'s "config wins" semantics — creates if absent (source tagged `"config"`), updates in place if the existing row is itself config-sourced, returns `ErrConflict` if an admin already registered a node under that name. Config never silently clobbers an admin-registered node.
  - `cmd/spidercob`: on every startup, bootstraps `cfg.Nodes` into the store via `UpsertConfigNode`, then rebuilds `cfg.Nodes` from a single `store.ListNodes()` call before `proxy.New`, `authserver.Config`, and `pin.SchedulerConfig` are constructed — **zero internal changes** to any of those three packages. This was the actual crux of the issue: `proxy.Gateway`, `authserver.AuthServer`, and `pin.Scheduler` each independently build a write-once-at-construction node registry, discovered during this issue's seam-check, which is why "node registration" couldn't just mean "add a store table + admin endpoint" the way agents/groups/policies did in issue #13.
  - `internal/adminapi`: `GET/POST/DELETE /admin/nodes`, behind the same dual-trust gate issue #13 built (no new auth work needed). Delete refuses a `source: "config"` row with an explanatory message — deleting it here would just have it reappear on the next restart, same reasoning `DeleteGroup` already applied to its own referential check.
  - **Deliberate scope cut, recorded in `MASTER_PLAN.md`'s decisions log: no hot-reload.** A node registered via `POST /admin/nodes` is persisted and listed immediately, but only becomes routable/mintable after the next gateway restart. This is explicit and tested, not papered over.
  - `automation/run-e2e-nodes.sh` (new, wired into `make ci`) — the **first e2e script in this repo's history to actually kill and relaunch the compiled binary mid-script**. Registers a node via the admin API against a gateway running with zero configured nodes, confirms it's listed but **not yet reachable** (`/mcp/echo/` 404s, and minting a per-node token for it fails) on the still-running process, then restarts the same binary against the same `store_db_path` and confirms it's now really reachable — a real session, a real `tools/call`. Proves the restart-required behavior against the real process lifecycle, not just a doc comment.
- `make ci` now runs **eight** Docker-free layers: `run-tests.sh`, `run-e2e.sh`, `run-e2e-auth.sh`, `run-e2e-policy.sh`, `run-e2e-pin.sh`, `run-e2e-schema.sh`, `run-e2e-adminapi.sh`, `run-e2e-nodes.sh`. `make ci-interop` (real Keycloak, Docker-required) is unaffected and still green.
- **Auth model recap (unchanged since issue #13, `MASTER_PLAN.md` §6, 2026-08-08):** the gateway does **not** get its own admin login. `/admin/*` (now including `/admin/nodes`) is gated by two independent checks, both required: (1) a service-to-service NHI bearer token scoped to a reserved `authserver.AdminResource` (`_admin`) audience, mint-restricted to a config allowlist; (2) a live introspection call against spider-snoop's own `GET /api/users/me`. A standalone shared login/tenant-management service (serving both products) remains explicitly deferred, not rejected — the `SpiderSnoopIntrospector` interface is the seam that would make adopting one later a config swap, not a gateway rewrite.
- **`dlp-scan` pre-commit hook**: fixed on the user's end mid-session-before-last (diff-scoped + context-score-gated rewrite). Both issue #13's and issue #15's commits went through cleanly, unblocked.
